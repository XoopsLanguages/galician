Axuda: Modelos

Descrición

XOOPS permite algunha separación entre a presentación real do sitio (o “pel” ou interface de usuario) e o código que se executa na parte traseira. O primeiro é xestionado por un mecanismo sofisticado baseado en temas gráficos. Un tema pode incluír, na súa forma básica, o HTML esencial. modelos que definen a interface visual do sitio, así como as follas de estilo e imaxes necesarias para complementar esa interface visual. Os temas son cambiables na interface administrativa, polo que cambiar a aparencia completa dun sitio XOOPS é só cuestión de cambiar o valor dun selector e premendo en "Aceptar". XOOPS tamén ofrece aos administradores do sitio a posibilidade de que os usuarios elixan entre algúns temas dispoñibles.

En xeral, a theme é o marco visual de alto nivel dun sitio: o tema define, por exemplo, o deseño xeral do sitio; por outra banda, non adoita definir a distribución específica dos contidos dentro dun bloque. Isto é xestionado por a entidade diferente chamada a conxunto de modelos. Un conxunto de modelos é un conxunto de modelos HTML que definen a presentación do contido dentro de todos os bloques que forman un sitio web de XOOPS. Se queremos unha metáfora máis clara para isto, poderiamos dicir que o tema é como o arquitecto dunha casa, mentres que o conxunto de modelos é como o decorador de interiores. O primeiro pon os muros e define a distribución xeral, pero é o segundo quen se encarga de “vestindo” esas paredes.

Se o tema activo é sinxelo que só inclúe un ficheiro de tema, ficheiros CSS e algunhas imaxes, XOOPS emprega o conxunto de modelos predeterminados para definir a presentación dos bloques. Non obstante, algúns temas complexos son o suficientemente sofisticados como para incluír o seu propio conxunto de modelos. Neste caso, o sitio o administrador debe usar a interface administrativa para configurar tanto o tema como o conxunto de modelos.

Como é o tema maxia Tema logrado? É dicir, como poden os modelos HTML incluír contido dinámico? Isto non se fai con espellos e fume, senón cun intelixente motor de modelos chamado Intelixente que fai a función do que antes se chamaba interpolación variable. Expresado dun xeito sinxelo, poderiamos dicir que o sistema XOOPS utiliza ficheiros PHP para albergar a lóxica dos módulos (acceso á base de datos, asignación de variables, xestión de dereitos...), ficheiros HTML con variables Smarty inseridas para xestionar o interface visual real e o motor Smarty para inserir valores e cadeas en lugares específicos dentro do HTML que constrúe as páxinas vistas polo usuario final. Con todo, o que isto significa para ti pódese resumir facilmente: grazas ao seu sistema de temática, XOOPS permite aos deseñadores de sitios crear máis sitios interesantes e visualmente abraiantes sen moita preocupación polo que ocorre baixo o capó.

Clonación e descarga de conxuntos de modelos

Se desexa crear un conxunto de modelos personalizados, pode facer unha copia do conxunto predeterminado (ou calquera outro) seleccionando oclon’ (solicitarase que lle dea un nome ao novo conxunto). A diferenza do predeterminado, outros conxuntos de modelos pódense editar libremente. Tamén pode gardar unha copia de a o modelo configurado no disco seleccionando odescargar’ ou elimínaa co ‘eliminar. Ás veces tamén podes ver un "Xerar’ xunto aos novos módulos para os que aínda non se crearon modelos.

Editando modelos

Podes ver unha lista completa de modelos dispoñibles navegando pola árbore de directorios. Cando seleccione un modelo, XOOPS abrirao nun editor onde pode editalo.

Durante a edición de modelos, debes activar unha preferencia que actualice automaticamente os ficheiros .tpl de modelos de módulo se hai ficheiros máis novos no directorio temas/o teu tema/modelos para o tema actual (Módulo do sistema -> Preferencias -> Configuración xeral -> Actualizar ficheiros .tpl do modelo do módulo). desde temas/o teu tema/directorio de modelos? -> 'Si’). Isto debería desactivarse unha vez que o sitio se faga público.

Se estragas un modelo accidentalmente, non esquezas que podes recuperar un "ben’ copiar desde o conxunto de modelos predeterminado. Se está a traballar con modelos non estándar, pode ser unha boa idea gardar unha copia no disco antes de comezar a modificalos.
